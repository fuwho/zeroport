Identity-native zero-trust access

To defend a network,
we first have to expose one.

Every VPN gateway, firewall and bastion host must listen on a public address. Anything that listens can be scanned, mapped, flooded, and exploited before a patch exists. We have been guarding the door instead of removing it.

ZeroPort removes the door. Nothing listens. There is no address to scan — yet authorized peers connect in seconds, at full speed.

01 — The paradox

Scan it. You will find nothing.

A scanner sweeps the internet looking for something that answers. ZeroPort's protected services answer nothing, because nothing is listening. The obvious question is how anyone legitimate ever gets in.

Why this is different. Port-knocking and single-packet authorization still run a daemon that listens for the knock — there is still a surface, and still a packet to replay or fuzz. ZeroPort has no listening surface to address at all.

03 — Why it is safe

Three guarantees you can test.

Removing the door is not enough on its own. These are the properties that make the result trustworthy — each one is a mechanism, not a promise.

GUARANTEE 01 — NO SINGLE ADMINISTRATOR CAN BETRAY IT ILLUSTRATION

The roster is signed by a key that is split across three officers. Choose who signs and watch what the network does.

Select at least one officer.
GUARANTEE 02 — ACCESS EXPIRES BY ITSELF ILLUSTRATION

Authorization is a short lease, not a permanent membership. It has to be renewed while a device stays healthy and reachable.

So a stolen laptop, switched off in a bag, loses its access on its own. Nobody has to notice. Nobody has to press revoke.

04 — What is actually built

The mechanisms above are implemented and tested.

Everything on this page is an illustration of how the system works. The system itself is real code with no third-party dependencies, and it runs from a terminal.

15/15
BIP-340 Schnorr
Identities on secp256k1 — the exact scheme Nostr uses. Checked against the specification's own test vectors.
13/13
FROST threshold signing
Two of three officers emit one 64-byte signature. A lone officer cannot forge it — the mathematics refuses.
13/13
Noise IK handshake
WireGuard's own handshake, with per-session forward secrecy and a replay window.
12/12
Nostr control plane
A real relay speaking NIP-01 over WebSocket. The roster is a signed, replaceable event.
4/4
Tor onion rendezvous
A genuine v3 onion service. Data written and read back through real Tor circuits.
3/3
WireGuard kernel tunnel
A real kernel interface whose peer list is controlled by threshold signatures.
Stated plainly. This page is a teaching tool, not a live network — the widgets above illustrate mechanisms rather than execute them. The working system, its test output, and an operations console that shows real data all live in the repository. One gap remains: everything runs on a single machine, so NAT traversal and wide-area latency are not yet demonstrated.
